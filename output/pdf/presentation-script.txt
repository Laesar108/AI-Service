5분 발표 원고

[0:00-0:40 / 1쪽 / 선택 과제와 수정 기능]
과제 1인 기존 AI Agent 기능 개선을 진행했습니다. 초기 답변은 CPU 한 번의 관측으로 지속 고부하를 단정하고, 조회하지 않은 로그를 분석했다고 설명했습니다. 이를 개선하기 위해 대상 확인과 진단 근거 도구를 추가하고, Runbook 검색을 RAG로 변경했습니다. 지표·로그·Runbook 전문 분석을 분리하되 필요한 역할만 호출하도록 구성했습니다.

[0:40-2:00 / 2쪽 / 구현 결과]
화면처럼 관측, 판단 한계, 조건부 조치를 구분하도록 바꿨습니다. 초기에는 로그를 분석했다고 단정했지만 현재는 로그와 시계열이 없음을 설명하고, 지속 고부하를 확인한 뒤 증설하도록 답합니다.
10개 평가 사례를 3번 실행했고, 마지막 사례는 2턴이어서 버전별 응답은 33건입니다. 대상 선택 정확성은 90.9%에서 100%로 높아졌고, 필요한 Runbook의 재현율은 77.8%에서 100%로 높아졌습니다. 다만 불필요한 문서도 포함되어 검색 정밀도는 낮아졌습니다. 총 토큰은 2.61배, p95 응답시간은 36.8% 증가했습니다.
동일 기준으로 다시 채점했을 때 현재 자동 점수가 높았지만, 평가자가 남아 있는 오류를 놓쳤습니다. 따라서 결론은 기존 회귀 사례의 개선이며, 새 질문에서도 전체 성능이 향상됐다고 단정하지 않았습니다.

[2:00-2:25 / 3쪽 / Agent Graph 구조]
초기는 research와 replan_check를 순환하며 문서를 보강하는 구조였습니다. 현재는 target으로 대상을 확인하고, Research 뒤에 역할 선택과 세 개의 분기를 배치했습니다. 마지막에는 검증 실패를 강제 통과시키지 않고 Fallback으로 종료합니다.

[2:25-3:10 / 4쪽 / Agent Graph 코드]
build_graph에서 select_research 뒤로 지표·로그 전문가와 Runbook 검색·분석 분기를 연결합니다. workers 목록에서 supervisor_join으로 연결한 Edge는 세 분기가 모두 끝난 뒤 결과를 합칩니다. worker_node에서는 enabled가 false이면 skipped를 반환해 실제 모델 호출을 생략합니다. validate의 조건부 Edge는 통과, 한 번 재작성, 한도 초과 시 제한 답변으로 나눕니다. 그래프 노드를 늘리는 것과 함께 호출 조건과 종료 조건을 명확히 한 변경입니다.

[3:10-4:00 / 5쪽 / MCP 코드]
MCP에서는 get_diagnostic_evidence를 추가했습니다. 기존 모니터링 Tool만으로는 알 수 없는 로그, CPU 시계열, 배포 자료를 반환합니다. availability와 records를 분리해 자료가 없는 상태를 정상으로 해석하지 않도록 했습니다. 에이전트에서는 작업 종류에 따라 모니터링 또는 진단 Tool을 호출하고, 근거 ID와 재시도 횟수를 저장합니다. 현재 자료 원천은 모의 JSON이며 실제 운영 시스템 연동은 아닙니다.

[4:00-5:00 / 6쪽 / RAG와 LCEL 코드]
RAG에서는 질문과 서비스별 관측 알림을 각각 검색합니다. 문서와 검색어의 임베딩을 정규화하고 유사도로 순위를 매깁니다. select에서 임계값과 상위 개수로 후보를 제한하고, search에서 문서 ID로 중복 제거합니다. 검색어당 한 문서여도 여러 검색어의 결과를 합치므로 다중 Runbook 검색이 가능합니다.
벡터는 SQLite에 보존하고 문서나 모델이 변경된 경우에만 해당 문서를 다시 임베딩합니다. 모델 호출은 LCEL로 프롬프트, 모델 어댑터, 파서를 연결해 공통화했습니다. 전체 작업은 LangGraph가 제어하고, 개별 모델 호출은 LCEL이 담당하는 구조입니다.

참고 자료: 7쪽 적용 범위, 8쪽 처리 효율·비용, 9쪽 동일 기준 재채점, 10쪽 한계·후속 개선.
시간은 발표 목표 배분이며 실제 말하는 속도에 맞춰 연습하면서 조정합니다.
